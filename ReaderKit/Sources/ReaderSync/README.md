# ReaderSync

FreshRSS-only Google-Reader-API client and device-local Keychain credentials. No legacy Account, parser, FMDB, CloudKit, or private service keys are linked.

`FreshRSSClient(repository:credentials:session:)` owns `refresh(account:)`, `flush(account:)`, and confirmed feed/folder mutations. `KeychainCredentialStore(service:)` stores API passwords under an app-specific service (use the Debug bundle identifier for Debug).

Every operation is serialized per account across its network suspension points. Refresh applies one authoritative snapshot only after every page and content batch succeeds. It never uses a publication-time `ot` cutoff. Pending read/star changes are sent before refresh and acknowledged using the exact outbox UUIDs; the repository protects newer pending state. Missing requested content, malformed JSON, non-success HTTP, and failed mutations propagate errors. API auth and write tokens renew once on authorization rejection, without logging passwords or tokens.

The installation root or explicit `/api/greader.php` URL is accepted. Credentials are the FreshRSS username and separate API password, not browser/SSO credentials. HTTP is accepted for explicitly configured self-hosted installations; HTTPS is recommended. The client downloads complete ID lists and article contents in batches of 500; no silent page limit is applied. Live FreshRSS integration remains a separate acceptance criterion.

`IconService.icon(for:)` keeps homepage jobs independent and coalesces consumers of the same URL. It bounds active jobs (three by default), streams at most 1 MiB per image / 512 KiB per HTML response, accepts image MIME types, and caches at most 32 successful results for one day. A failed homepage still tries its origin's `/favicon.ico`; transient or missing icons are not permanently cached. Cancellation of the last consumer cancels the shared request and prevents further candidates. Image decoding is left to a display-context-aware caller; this module does no UI-actor decoding.

`OPMLImportService(repository:client:).importDocument(_:account:)` validates the entire OPML document before writes, coalesces identical subscriptions and rejects the same URL under conflicting category paths. FreshRSS receives the full joined folder path (`A/News`, `B/News`) as a flat category name. The original path and optional homepage are retained locally in `FeedPreferences`, using the repository's atomic import-metadata merge so concurrent edits to digest mode, cloud permission or timezone cannot be overwritten. `FreshRSSClient.addSubscription(...)` returns the confirmed `FeedKey` from the API, so redirects cannot misassign metadata. The original imported URL is retained for idempotent repeated imports even when FreshRSS canonicalizes that URL. Server mutations cannot be rolled back as one document-wide transaction; on failure the error is propagated and a repeated import reuses already confirmed subscriptions.
